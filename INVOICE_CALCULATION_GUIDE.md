# 📊 Invoice Report Calculation Guide

## System Overview

The Invoice Report Table is generated through a multi-step process involving:
1. **Activities** - Define work packages with monthly work distribution percentages
2. **Cost & Sales** - Assign financial values to activities
3. **Invoice Milestones** - Define project milestones and sub-milestones with percentages
4. **Activity-Milestone Matching** - Link activities to sub-milestones, specifying work distribution
5. **Sales Source Selection** - NEW: Each sub-milestone specifies which activities' sales to use for calculation
6. **Calculation Engine** - Combines all data using a formula

---

## Step 1: Activities Input (activities.csv)

### What is an Activity?

An activity represents a **work package or task** in your project with:
- **Activity Name** - Main category (e.g., "Design", "Development")
- **Sub-Activity** (optional) - Subcategory (e.g., "UI Design", "Backend Development")
- **Start Month & End Month** - Timeline for the activity
- **Monthly Percentages** - Work distribution across months (must total 100%)
- **Cost & Sales** - Financial values (stored in cost_sales.csv)

### Example Activity Entry

| Activity | Sub-Activity | Start | End | Jan | Feb | Mar | Apr | Cost | Sales |
|----------|-------------|-------|-----|-----|-----|-----|-----|------|-------|
| Development | Frontend | Jan | Mar | 30% | 40% | 30% | - | - | - |
| Development | Backend | Jan | Apr | 20% | 20% | 30% | 30% | - | - |

**Meaning:**
- Frontend work: 30% in Jan, 40% in Feb, 30% in Mar (total 100%)
- Backend work: 20% in Jan, 20% in Feb, 30% in Mar, 30% in Apr (total 100%)

## Step 2: Cost & Sales (cost_sales.csv)

### What are Cost & Sales?

- **Cost** - Expenses associated with the activity
- **Sales** - Revenue/value generated by the activity (used in invoicing calculations)

### Example

| Activity | Sub-Activity | Cost | Sales |
|----------|-------------|------|-------|
| Development | Frontend | 50,000 | 100,000 |
| Development | Backend | 75,000 | 150,000 |

---

## Step 3: Invoice Milestones (invoice.csv)

### What is a Milestone?

A milestone is a **billing point** in your project with:
- **Milestone Name** - Main milestone (e.g., "Project Delivery")
- **Sub-Milestone** - Payment phase (e.g., "Phase 1: Design", "Phase 2: Development")
- **Percentage** - What % of the linked activities' sales to invoice
- **Sales_From_Activities** - NEW: Which activities to pull sales from (comma-separated)
- **Description** - Optional notes

### Example

| Milestone | Sub-Milestone | Percentage | Sales_From_Activities |
|-----------|---------------|-----------|----------------------|
| Project Delivery | Phase 1: Design | 25% | Design, Requirements |
| Project Delivery | Phase 2: Dev | 50% | Development |
| Project Delivery | Phase 3: Testing | 25% | QA, Testing |

---

## Step 4: Activity-Milestone Matching (activity_milestone_matching.csv)

### What is Matching?

Matching **links activities to sub-milestones** and specifies the **work distribution timing**.

### Example

| Activity | Sub-Activity | Sub-Milestone | Milestone | Work Distribution |
|----------|-------------|---------------|-----------|-------------------|
| Development | Frontend | Phase 2: Dev | Project Delivery | 50% March, 50% April |
| Development | Backend | Phase 2: Dev | Project Delivery | 30% March, 70% April |
| Design | UI Design | Phase 1: Design | Project Delivery | 50% Jan, 50% Feb |

**Meaning:**
- "Phase 2: Dev" sub-milestone is linked to Frontend and Backend activities
- Frontend work is 50% in March, 50% in April (for invoicing purposes)
- Backend work is 30% in March, 70% in April

---

## Step 5: Sales Source Selection (NEW)

### What is Sales_From_Activities?

Each sub-milestone specifies **which activities' sales values** to use for the invoice calculation.

### Why?

Some milestones might:
- Be linked to activities without sales (e.g., support activities)
- Need sales from multiple unrelated activities
- Reference only specific activities' sales

### Example Scenario

**Problem:** 
- Sub-milestone "Phase 2: Dev" is linked to Activity "Development" (has sales)
- But also linked to Activity "Project Management" (no sales)

**Solution:**
- Set `Sales_From_Activities = "Development"` for Phase 2: Dev
- Now only Development's sales ($150,000) are used, not Project Management

---

## Step 6: Calculation Formula

### Core Formula

For each **Sub-Milestone** and **Month**:

```
Invoice Amount = (Sub-Milestone % / 100) × 
                  (Sum of Linked Activity Work Distribution %) × 
                  (Sum of Sales from Specified Activities)
```

### Step-by-Step Calculation

#### Example Setup:
- **Sub-Milestone:** "Phase 2: Dev" (50% of total)
- **Sales_From_Activities:** "Development Frontend", "Development Backend"
- **Linked Activities (from matching):**
  - Frontend: 50% in April, 50% in May
  - Backend: 30% in April, 70% in May
- **Sales:**
  - Frontend: $100,000
  - Backend: $150,000

#### April Calculation:

1. **Get sub-milestone percentage:**
   ```
   Milestone Percentage = 50%
   ```

2. **Sum linked activity work distribution for April:**
   ```
   Frontend April: 50%
   Backend April: 30%
   Total Work Distribution = 50% + 30% = 80%
   ```

3. **Sum sales from specified activities:**
   ```
   Frontend Sales: $100,000
   Backend Sales: $150,000
   Total Sales = $100,000 + $150,000 = $250,000
   ```

4. **Apply formula:**
   ```
   Invoice Amount = (50% / 100) × (80% / 100) × $250,000
                  = 0.50 × 0.80 × $250,000
                  = $100,000
   ```

**Result:** Phase 2: Dev invoices $100,000 in April

## Step 7: Invoice Report Table Output

### What is Generated?

A table with:
- **Rows:** All sub-milestones
- **Columns:** Each month in project timeline
- **Values:** Invoice amount for that sub-milestone in that month

### Example Output

| Sub-Milestone | January | February | March | April | May | **TOTAL** |
|---------------|---------|----------|-------|-------|-----|-----------|
| Phase 1: Design | $12,500 | $12,500 | - | - | - | $25,000 |

## Key Differences: Before vs After

### BEFORE (Original System)
```
Invoice = Milestone % × Linked Activity Work % × Linked Activity Sales
```
- Only used the linked activity's sales
- Problem: Linked activity might not have sales value

### AFTER (New System)
```
Invoice = Milestone % × Sum(Linked Activity Work %) × Sum(Specified Activity Sales)
```
- Can specify which activities to pull sales from
- Each sub-milestone has independent control
- Problem solved: Can pull sales from unrelated activities

## Example Workflow

### Scenario: IT Project with 3 Phases

**Step 1: Create Activities**
- Activity "Analysis" - Sales: $50,000
- Activity "Development" - Sales: $120,000
- Activity "Testing" - Sales: $30,000
- Activity "Project Management" - Sales: $0 (support activity)

**Step 2: Create Invoice Milestones**
- Milestone: "Project Delivery"
  - Sub: "Analysis Phase" (20%) → Sales from: "Analysis"
  - Sub: "Dev Phase" (50%) → Sales from: "Development"
  - Sub: "Testing Phase" (20%) → Sales from: "Testing"
  - Sub: "Management" (10%) → Sales from: "Analysis, Development, Testing"

**Step 3: Link Activities to Sub-Milestones**
- Match "Analysis" activity to "Analysis Phase" (100% in Jan-Feb)
- Match "Development" activity to "Dev Phase" (40% Mar, 60% Apr)
- Match "Testing" activity to "Testing Phase" (50% May, 50% Jun)
- Match "Project Management" to all phases

**Step 4: Calculate Invoicing**

**Analysis Phase (Jan):**
```
= 20% × 100% × $50,000 = $10,000
```

**Dev Phase (Apr):**
```
= 50% × 60% × $120,000 = $36,000
```

**Management (Jan):**
```
= 10% × 100% × ($50,000 + $120,000 + $30,000) = $20,000
```

## Summary

The Invoice Report Table is generated by:

1. **Collecting** activity work percentages from monthly schedules
2. **Looking up** sales values from cost_sales.csv
3. **Reading** which activities to use sales from (Sales_From_Activities)
4. **Matching** activities to sub-milestones
5. **Applying** the formula: `Milestone % × Work % × Sales`
6. **Aggregating** by month and sub-milestone
7. **Displaying** as a clean table with totals

This allows **flexible invoicing** where each sub-milestone can draw sales from any combination of activities, solving the problem of activities without sales values.
